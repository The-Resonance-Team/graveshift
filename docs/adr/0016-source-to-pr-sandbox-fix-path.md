# The fix path reads real source, verifies in a sandbox, and publishes a draft pull request

Status: accepted

On 2026-11-22 ticket #59 made the fix path a real source-to-PR flow. Before this change the path stopped early: the diagnosis context provider always failed closed, so no model call, no source read and no pull request happened. The ADR records what the path now does and which seams keep it safe and testable.

## Contract

A model reply is a **Patch proposal**: `{ baseSha, files: [{ path, baseBlobSha, diff | content, linesChanged }] }`. One file carries a unified diff or full text, never both. A new file names the git empty-blob SHA. The proposal is pinned to one base commit and to the base blob of every file it changes.

`packages/patch` holds `applyUnifiedDiff` and `resolvePatch` as pure functions. A proposal fails when the base SHA moved, when a base blob SHA no longer matches, or when a hunk's context no longer matches. Full file text is derived after apply, so the base cannot move under a change and the guard always checks the resolved content. `guardPatch` keeps its full-content contract. `PatchSchema` stays the guard and fixer contract.

## Seams

- `SourceProvider` (`packages/fixer/src/source.ts`) reads the base ref, the recursive tree and every blob through the injected `GitHubClient`, which gained `listTree` and `getBlobBytes`. The real implementation reads only: every failure throws, so a fix fails closed instead of continuing on partial source. Binary blobs keep exact bytes and carry no text. The read is bounded: 5000 tree entries, 1 MiB per blob and `MAX_TOTAL_SOURCE_BYTES` (32 MiB) in total, accumulated in one array.
- `FixWorkspace` (`packages/fixer/src/sandbox.ts`, with the subprocess runner in `packages/fixer/src/spawn.ts`) writes the base bytes to a throwaway directory, applies the resolved patch, then runs the configured check commands. Check commands come only from `fix.sandbox.commands` in the committed config file, never from the model or the repository. An empty command list blocks every fix. Each command runs with a built environment: `PATH` is `/usr/bin:/bin` plus the owner-set absolute directories in `fix.sandbox.pathDirs` (there is no implicit host `PATH`, so a command whose runtime is outside those directories cannot start and the fix is blocked), `HOME` is the checkout, and beyond those only the named non-secret variables of `SANDBOX_ENV_ALLOWLIST`, so no model key, GitHub App key or other secret reaches the process. Each check runs under a per-OS network jail (`sandbox-exec` on macOS, `unshare -rn` on Linux, which needs no extra privilege). The jail is proven, not assumed: one trivial command starts under it first, and a platform with no jail that can start blocks every fix. Every command has a timeout that kills the process and its group, and stdout and stderr are capped at `SANDBOX_OUTPUT_CAP` bytes each: the runner reads the pipes while the command runs, drains what is over the cap without storing it, and puts a bounded drain after the command exits, so neither a chatty check nor a grandchild that inherited a pipe can grow memory or hold the run open. A check that never starts, fails, or times out is still recorded in the `CheckOutcome` list. `packages/fixer/src/spawn.ts`, `docs/SECURITY.md` and this ADR state the one limit the jail does not cover: file access.
- `openDraftPr` takes the pinned base `{ sha, treeSha }` and re-checks the live ref before its first mutating call, so a base that moved after the read raises `StaleBaseError` and nothing is pushed. The tree is built against the pinned base tree. The client still has no merge method, the pull request is still a draft, and `guardPatch` still runs before any client call. The body carries identifiers, check results and diff stats only. The work item title, the root cause and a Fix now note stay on the work item and in the API result: fewer copies of request text mean a smaller surface that has to stay redacted, and the pull request is a code review artifact, not an incident report.
- `FixContextProvider` is real. `apps/api/src/fix/fix.context.ts` builds confidence, category and signals from the triage labels on the Work item, and the counters from stored Work item data and the gateway audit ledger. A missing or malformed label fails closed before any source read, model call or GitHub call.

`FixDeps` gained `source`, `workspace`, `sandbox` and `now`. `PrRef` gained `openedAt`: the time Graveshift opened the pull request, which is the source for the open-PR-per-hour policy counter. New failure codes `source_unavailable`, `checks_failed` and `stale_base` are part of the wire contract.

## Order

The order is fixed: context, then `decide()`, then the repository service mapping, then the source read, then the model call, then resolve and guard, then the sandbox checks, then the stale-base re-check, then the push and the draft PR. Nothing after the policy gate can grant permission: model output is data, the source text enters the prompt wrapped as untrusted data, and only a passed verification publishes. The service mapping is part of the gate, not of the client: `apps/api/src/fix/fix.service.ts` rejects a work item whose `service` is not in `policy.github.repos[].services` before it reads a byte of source or calls the model, and `openDraftPr` keeps the same check as the last line before any mutating call.

## Limits the jail does not cover

The jail blocks network only. A check command runs as the daemon's OS user, so it can read files that user can read outside the throwaway checkout and write outside it. An OS-level file jail was tried and rejected: a macOS `sandbox-exec` profile that denies `(file*)` also denies the runtime's own reads and needs a per-command allowlist no deployment can predict, and a Linux mount namespace with a read-only bind of the workspace needs `CAP_SYS_ADMIN` or a writable-root user namespace, which shared CI runners and hardened hosts deny — the same reason the committed tests fall back to an unjailed but still fully separated subprocess there. So the boundary is stated instead of half-enforced: the check commands are owner-written config, the daemon runs as a dedicated least-privilege user, and that user's home directory must hold no secret file. `docs/SECURITY.md` records the same limit and the owner duties that go with it.

## Offline testing

Committed tests use the `emulate` GitHub and AI emulators plus injected fakes. No test uses a real model key, makes a real GitHub call, sends a secret, or touches the network. The e2e suite seeds real repository files through the emulator contents API, reads the real base, tree and blob SHAs, answers the model with a canned proposal pinned to those SHAs, and reads the pushed head tree back as real git objects to prove the diff landed. The e2e also proves the gate order: a policy denial and an unmapped service both stop the run with zero source reads, zero model calls and zero GitHub calls, and a published body that holds no work item title, root cause or Fix now note. The sandbox check commands run for real through the production spawn runner, so the child process sees only the built environment. `packages/fixer/src/spawn.test.ts` pins the jail argv, the environment allowlist, the timeout kill, the process-group kill and the bounded pipe read that keeps a grandchild from hanging a run, the 64 KiB output cap on a command that prints far more, and the fail-closed default when no jail can run; the same file proves a check whose runtime is outside `PATH` cannot start and the same check runs once the owner-set directory is added. `apps/api/src/fix/fix.committed-checks.test.ts` runs the exact commands from the committed `graveshift.config.yaml` through the real sandbox and proves they start and pass. Where the host can start the platform jail the e2e runs under it; where the host refuses one (GitHub-hosted Ubuntu blocks unprivileged user namespaces) the e2e still starts every check as a real subprocess without the jail prefix.

## Deferred

The daemon read surface (ticket #48) has no writers, and its counters answer `source: 'not_wired'`. The local provider therefore derives confidence, category and signals from triage labels and the counters from the store and the in-process gateway spend ledger, each marked with a `ponytail:` comment and an upgrade trigger. `actionsLast10Min` and `diagnosisLoops` are structurally zero until the runtime-action ledger (#49) and the watcher loop (#61) exist. GitLab, GitHub Actions, dashboard UI and runtime actions stay out of scope.

Rejected alternatives: trusting a model-supplied full file text with no base pin (a newer commit could be overwritten); running checks on the developer checkout or with inherited environment (a leak of secrets and network); publishing then waiting for CI to fail (a draft PR would still advertise an unverified change as the fix).

Trade-off: the fix path now makes more read calls before the first mutation, and the owner must supply check commands per deployment. In exchange a pull request only appears when the change applies to the exact base, the guard accepts the resolved content, and the configured checks pass without secrets or network.
