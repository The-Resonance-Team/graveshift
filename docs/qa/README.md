# QA reports

Start with the current summary for the area under review:

- [Console: current QA status](console/latest.md)

Each area keeps a `latest.md` summary and dated evidence under `runs/YYYY-MM-DD/`. Update the summary when findings change. Add a new run for a new sweep; keep earlier screenshots and results for comparison. If a prior report is wrong, correct it in place and explain the correction rather than silently rewriting history.

Each run should identify its routes, widths, fixture or live-data scope, functional coverage, checks, findings, evidence, and blocked or untested work. A route screenshot or HTTP 200 alone is not a functional pass.
